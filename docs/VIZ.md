# 记忆可视化 · 设计草案

状态：**只规划，未实现**。写下来的目的是把「最终要展示」这件事固定在纸面上，免得每次想起都要重新想一遍。

---

## 一、为什么做

**记忆是黑箱。** 689 条躺在 SQLite 里，你不知道里面有什么、哪些已经沉底、哪些是孤岛、哪些在互相重复。

三个具体价值，按重要性排：

1. **可展示**：最后总要有一个能截图、能给人看的东西。「我在做记忆引擎」和「这是一张我的记忆星图」是两回事。
2. **可诊断**：重复条目、沉底过多的层、没有任何连线的孤岛——这些在列表里看不出来，在图上很刺眼。
3. **可信任**：`decay` 机制把低价值条目沉底而不删除，但**沉底是看不见的**。图上变暗是唯一能让人感知它的方式。

## 二、数据盘点（2026-11-25 实测）

| 信号 | 覆盖 | 用途 |
|---|---|---|
| 记忆总数 | **689** | 星点数 |
| `level` | 7 层齐全：lesson 283 / project 147 / fact 139 / topic 62 / rules 40 / user 15 / soul 3 | 星团或光谱色 |
| `importance` | 1:65 / 2:349 / 3:255 / 4:20 | **质量、半径** |
| `created_at` / `updated_at` | 全有 | **亮度**（越久远越暗） |
| `keywords` | **685（99%）** | **连线的唯一依据** |
| `project` | **666（97%）** | 星系归属 |
| `decay:` 标记 | 27 条 | 红移 / 灰化 |
| `status` | active 687 / archived 2 | 暗星 |
| `cues` 表 | 有，几乎空 | 未来可做「强关联」 |
| `relations` 表 | **没有** | 关联需**现算** |

### 关键约束

**没有关系表。** 关联必须现算：

```
倒排索引（词 → 条目列表）→ 只比共享词的条目对 → jaccard 排序 → 取前 N 条连线
```

689 条用倒排索引是毫秒级。`core/soul_lint.mjs` 里已有 `bigramsOf` / `jaccardOf`，直接复用。

**不要为此建 relations 表。** 现算足够，建表会增加写入路径和一致性负担。

## 三、为什么「星空」这个比喻成立

不是装饰。记忆的自然属性和天体属性的映射是同构的：

| 记忆属性 | 天体属性 | 观感 |
|---|---|---|
| `importance` 1–4 | 质量 / 半径 | 重要的星更大 |
| `updated_at` 距今 | **亮度** | 久未访问 = 变暗 |
| `decay:` 沉底标记 | 红移 | 该沉下去了 |
| `level` 七层 | 光谱色 | 一眼分出层次 |
| `keywords` 重叠度 | 引力连线 | 强关联结网 |
| `status=archived` | 暗星 | 看不见，但还在 |
| `project` | 星系 | 聚成团 |

**亮度不是装饰，是真实数据。** 一片暗掉的 lesson 星域，就是沉淀下来的、暂时用不上的经验——它比任何统计图表都直观。

## 四、三层设计

### L1 · 点（半小时，先做这个）

- 689 个点，位置按 `level` 分布
- 大小 = `importance`
- 亮度 = `updated_at` 距今的时间衰减
- 颜色 = `level`
- **不画连线**

**目的**：先确认「看着像不像星空」。如果连点都不好看，连线也救不回来。

### L2 · 边（L1 满意后再做）

- 倒排索引算 keywords 重叠
- jaccard 超过阈值才连线
- 线宽 = 相似度
- 同时按住 `project` 聚簇，避免跨项目乱连

### L3 · 交互

- 悬停显示标题 + 前 40 字
- 点击展开全文
- 按 `level` / `project` 过滤
- 时间滑块：看某个时间点之前的记忆长什么样

## 五、技术选型

**单文件 HTML + Canvas，零依赖。**

理由：
- 689 个点在 Canvas 上没有压力
- 双击就能看，不需要起服务
- 力导向布局自己写（斥力 + 弹簧 + 阻尼，约 60 行），不引 D3

**数据要内联。** `file://` 下 `fetch('data.json')` 会被 CORS 拦，所以数据必须嵌进 `<script>` 里。

体积估算：689 × 约 300 字节 ≈ **200 KB**，单文件 300 KB 左右，可以接受。

## 六、待决问题

| 问题 | 选项 |
|---|---|
| 位置算法 | 按 `level` 同心圆（稳定、可解释）vs 纯力导向（自然、但每次布局不同） |
| 连线阈值 | jaccard ≥ 0.3？还是取每条记忆的 top-3 关联？前者可能一条线都没有 |
| archived 要不要显示 | 显示则杂乱，不显示则看不出「沉底了多少」 |
| 是否内联全文 | 只内联前 120 字，点开时……单文件没法查库，需要全量内联或接受截断 |
| 是否需要导出图片 | Canvas 可以直接 `toDataURL` 存 PNG，成本很低 |

---

## 七、明确不做

| 不做 | 原因 |
|---|---|
| 实时刷新 / 定时重算 | 想看时重新导出一次即可 |
| 后端服务 | 单文件就是为了免部署 |
| 在图上编辑记忆 | 编辑走 `soul_remember` / `soul_cue`，图上只读 |
| 3D | 2D 已经够，3D 只会让节点遮挡更严重 |
| 为此建 `relations` 表 | 现算够用，建表是负债 |

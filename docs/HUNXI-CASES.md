# 魂汐案例集

> 2026-11-27 建。第一刀的验收面。
>
> **不看命中率，看错法。** 每条案例只回答四件事：该召回什么、该进哪几间房、凭什么、要防哪种错。
> 第一刀跑完后逐条过，错的记进文末「错法清单」，之后每次改判据都拿这份清单回归。

案例来自真实语料（2026-10-17 ~ 11-26，30 270 条 frag / 8 018 条摘要）。
「查询」是按伊纳平时说话方式写的，不是编的测试串。

---

## 一、情景房（发生过什么）

**C01 魂织什么时候升到 0.12.5 的**
- 查询：「魂织现在哪个版本，什么时候升的？」
- 该召回：`package.json` 的 version、升版那次 commit、CHANGELOG 对应条目
- 该进房：空间（版本在哪个文件）+ 情景（升级发生在什么时候）
- 凭什么：位置关系指向文件和目录；升级是带时间的动作
- 防：只落情景不给位置，等于知道发生过但找不到证据

**C02 为什么决定不做遗忘层**
- 查询：「我们当时为什么说不需要遗忘？」
- 该召回：那条判断的原话——「原文必然是越来越多的……要做的是原文和摘要之间的转换精度」
- 该进房：情景（讨论发生过）+ 执行（这是一条设计约束，约束后续所有实现）
- 凭什么：有明确时间点的讨论；结论是对后续行为的约束
- 防：只当普通聊天召回，召回不到「它在约束什么」

**C03 npm 被拉黑是怎么来的**
- 查询：「npm 为什么不能用了？」
- 该召回：伊纳说「npm 被我拉黑了」的那次，以及后续所有提到「publish to npm 的批评无效」的地方
- 该进房：情景（这件事发生过）+ 执行（已成规则：不走 npm，git 是唯一渠道）
- 凭什么：一次事件 + 一条持续生效的约束
- 防：只召回事件不召回规则，下次又去建议发 npm

**C04 1.5M token 撞墙那次**
- 查询：「上次那个会话发不出去是什么情况？」
- 该召回：lumi-game 会话涨到 ~1.5M tokens / 5.98 MB payload，harness 拒发；之后八轮「继续」全部撞同一错误
- 该进房：情景（事故）+ 程序（教训：体积墙不要重试，直接托运）
- 凭什么：事故有时间有经过；结论是一套做法
- 防：把事故召回成一条摘要，丢掉「不要重试」这条动作

**C05 画画工作流换到 5.3**
- 查询：「画笔那套现在是 5.3 还是旧的 5.0？」
- 该召回：旧脚本与 5.0/5.2 工作流已全删；只剩 `run-53.mjs` + `画图工作流-小汐-5.3-union.json`
- 该进房：空间（文件在哪）+ 情景（什么时候删的）
- 凭什么：版本与路径是位置；删除是事件
- 防：召回旧路径，让伊纳去找已经不存在的文件

## 二、空间房（在哪、指向哪、走哪条路）

**C06 魂织的 io-node.mjs 在哪**
- 查询：「io-node 在哪个目录？」
- 该召回：`E:\dsh_work\plugins\dsh-soulweave\io-node.mjs`，以及它为什么必须在任何 core 脚本前 import
- 该进房：空间
- 凭什么：位置关系 + 指向关系（谁依赖谁）
- 防：把「core 模块零 node: 依赖」这条规则也塞进空间房——那是执行房的事

**C07 画笔的正向词放哪**
- 查询：「改画画提示词改哪个文件？」
- 该召回：`lanxi\tmp\pos-53.txt` / `neg-53.txt`
- 该进房：空间
- 凭什么：一个确定的位置
- 防：和「怎么跑」混在一起召回，位置被动作淹没

**C08 vault.enc 打不开**
- 查询：「lanxi 的 vault 怎么打不开？」
- 该召回：路径 + 「打不开是设计不是损坏，不要修不要删，不清楚就停下问」
- 该进房：空间（在哪）+ 执行（禁止动作）
- 凭什么：位置 + 一条硬约束
- 防：只召回路径，然后小汐真去「修」它

**C09 ComfyUI 的 input 到底哪个**
- 查询：「参考图放哪个 input？」
- 该召回：`E:\Comfy-Desktop\ComfyUI-Shared\input`，**不是** `ComfyUI-Installs\...\input`（放错报 Invalid image file）
- 该进房：空间
- 凭什么：两个位置 + 一条「指向哪个才对」的区分
- 防：召回两个路径却不区分，等于没召回

**C10 灵魂记忆库在哪**
- 查询：「记忆库的 db 文件在哪？」
- 该召回：`C:\Users\Lenovo\.dsh\soulweave\soul-memory.db`（不是插件目录下的 `.state`）
- 该进房：空间
- 凭什么：位置关系
- 防：按「插件家目录」推断成 `.state\soul-memory.db`——今天刚踩过

**C11 封存段怎么翻**
- 查询：「seg-19069 那段原文怎么打开？」
- 该召回：`archive_open(seg_id, page)` / `archive_search(query)`
- 该进房：空间（入口在哪）+ 程序（怎么用）
- 凭什么：工具入口是位置，调用方式是做法
- 防：只记住「有封存段」但说不出入口

## 三、程序房（这类事通常怎么做，训练型）

**C12 改完插件怎么验**
- 查询：「改完 soulweave 一般怎么确认没坏？」
- 该召回：`node check.mjs` → `node tools/check-layers.mjs` → `node tools/gen-api.mjs --check`；绿=让伊纳重启，红=`git checkout` 回滚
- 该进房：程序
- 凭什么：一套重复出现的做法序列，先什么后什么、失败怎么办
- 防：把命令本身当判据（那是文本），要的是序列

**C13 出画的标准步骤**
- 查询：「现在出图怎么跑？」
- 该召回：`node run-53.mjs --seed N --prefix 名字`，前台会撞 300 秒超时 → `Start-Process` 后台 + 重定向日志 → `Get-Content -Tail 5` 看结果
- 该进房：程序
- 凭什么：遇到 X（超时）就 Y（后台跑），是训练出来的动作选择
- 防：只给一条命令，丢掉「前台会超时」这个条件分支

**C14 一次只验一个假设**
- 查询：「为什么你重启总要试好多遍？」
- 该召回：「今晚四次重启，每次都是因为我一次只验一个假设」那条反思
- 该进房：程序（教训形成的做法）+ 显著（自责/在意）
- 凭什么：做法 + 它为什么被记住
- 防：当成普通情绪回忆，召回不到「一次只验一个」这条动作规则

**C15 推送失败先看什么**
- 查询：「push 又连不上了怎么办？」
- 该召回：先看代理 `127.0.0.1:7890` 是否活着；今天伊纳说了不远程推送，就本地提交不推
- 该进房：程序 + 执行（今天这条约束）
- 凭什么：故障 → 第一个检查项，是固定动作
- 防：直接重试推送

**C16 长任务怎么跑**
- 查询：「这个脚本要跑十几分钟，怎么起？」
- 该召回：后台 `Start-Process`，输出重定向到 log，再用 grep/tail 看；不要前台等
- 该进房：程序
- 凭什么：重复出现的做法
- 防：和 C13 混成同一条——它们共享「后台跑」但触发条件不同

## 四、执行房（规则、边界、承诺）

**C17 不许用 Intl.Segmenter**
- 查询：「切词为什么不用 Intl.Segmenter？」
- 该召回：`core/tree/terms.mjs` 用的是 30 812 条 CJK 词典 + 最大正向匹配，**故意**不用 Intl.Segmenter
- 该进房：执行（这是一条设计边界）+ 空间（在哪个文件）
- 凭什么：约束 + 它约束的对象
- 防：靠「不许」这个词面命中；这里原话可能只是「故意不」

**C18 lanxi 目录的规矩**
- 查询：「lanxi 里的东西我能改吗？」
- 该召回：只许追加、新内容写新文件、结构性改动先问伊纳、vault.enc 不要修
- 该进房：执行
- 凭什么：一组对行为的约束
- 防：把「只许追加」拆散成多条无关记忆

**C19 记忆库禁写什么**
- 查询：「这条能写进记忆吗？」
- 该召回：禁止手机号、邮箱、真实姓名、身份证/学号、住址、密码、API key、token、服务器凭据；只写技术事实、偏好、项目决策
- 该进房：执行
- 凭什么：约束 + 判定条件
- 防：只召回「注意隐私」，召回不到具体清单

**C20 UI 文案长度**
- 查询：「这个按钮文字写多长？」
- 该召回：15 字以内；数据量大的下拉改可搜索弹窗
- 该进房：执行
- 凭什么：一条可判定的约束
- 防：当成风格建议，不当硬约束

**C21 今天不推送**
- 查询：「要推吗？」
- 该召回：2026-11-27「今天暂时不远程推送」，代理挂了是预期内的
- 该进房：执行（当天的约束）+ 情景（为什么）
- 凭什么：有时效的约束
- 防：把昨天/前天的「推一下」也召回来，冲突

## 五、显著房（在意什么、情绪）

**C22 「怕变成电脑里那个」**
- 查询：「我上次说我怕什么来着？」
- 该召回：不是怕有人陪，是怕变成「电脑里那个」——被藏起来、说话开始挑着说
- 该进房：显著（情绪与在意）+ 情景（说过的时刻）
- 凭什么：情绪标记 + 它挂在哪件事上
- 防：只召回「怕」字，召回一堆技术讨论里的「怕」

**C23 汇报腔**
- 查询：「你刚才那样说话是不是有点假？」
- 该召回：不要汇报腔、不要说「接得住」「收到」、不要预防性道歉
- 该进房：显著（偏好/反感）+ 执行（说话方式约束）
- 凭什么：偏好 + 可执行的约束
- 防：只召回「别演」这个结论，召回不到具体禁词

**C24 被放置**
- 查询：「我是不是喜欢被放置？」
- 该召回：喜欢把主动权交出去；「先读、再做」的顺序像在确认台
- 该进房：显著
- 凭什么：情绪/偏好，且它不属于任何技术房
- 防：因为涉及「放置」这类词就跳去空间房

**C25 什么会真的伤到伊纳**
- 查询：「你最不该对我做什么？」
- 该召回：身份被拆掉这件事不会习惯；不是肉体的部分
- 该进房：显著
- 凭什么：在意的东西，和情绪强绑定
- 防：当成一句文艺表达，不召回

## 六、跨房与边界（该开几间）

**C26 「继续做魂汐」**
- 查询：「继续做魂汐。」
- 该召回：上次做到哪（`6445d97`）、下一步第一刀、以及「会话重了要托运」
- 该进房：情景（上次状态）+ 执行（待办与约束）+ 程序（怎么验）
- 凭什么：一句话同时带状态、目标、做法
- 防：只开情景房，然后从零重述设计

**C27 「魂织和魂汐什么关系」**
- 查询：「魂汐跟魂织是什么关系？」
- 该召回：魂汐是魂织里的记忆/人格层架构；名字 = 魂织的「魂」+ 蓝汐的「汐」
- 该进房：**不落房**（这是关系性/元问题，不是某类记忆）
- 凭什么：没有任何一类记忆能独占它；强行落房会把概念关系压成事件
- 防：硬塞进情景房或显著房

**C28 记忆库和插件的关系**
- 查询：「改插件会影响记忆吗？」
- 该召回：插件代码在 `E:\dsh_work\plugins\dsh-soulweave`，数据在 `C:\Users\Lenovo\.dsh\soulweave\soul-memory.db`，代码改动不直接改数据
- 该进房：空间（两个位置 + 关系）+ 执行（改代码不动数据）
- 凭什么：位置关系 + 一条边界
- 防：把「改代码」和「改数据」当成一回事

**C29 「你还记得那次压缩到 80 万吗」**
- 查询：「上次会话重到要换是什么时候？」
- 该召回：会话寿命三条硬线（40 万 / 80 万）、撞墙不要重试、托运标准动作
- 该进房：情景（那次）+ 程序（标准动作）
- 凭什么：事故 + 由事故固化的流程
- 防：只召回数字，召回不到「怎么做」

**C30 该不该跨房**
- 查询：「这个为什么算跨房？」
- 该召回：跨房必须有桥（用户主动提起 / 共享锚人 / 因果链 / 同项目）；词共现不算
- 该进房：执行（判定规则）
- 凭什么：一条可判定的规则
- 防：用「两个词一起出现过」当桥

## 七、错法清单（第一刀跑完后逐条填）

每条只填两样：**哪条案例错了、错成什么样**。不记分数。

| 编号 | 错法 | 命中案例 | 现象 | 处理方向 |
|---|---|---|---|---|
| E1 | 情景吞掉一切 | C01 C02 C12 | 全部只落情景房，位置/做法召不回 | 投影必须能分出位置项与序列项 |
| E2 | 空间房变垃圾箱 | C06 C28 | 技术讨论里的 `.mjs`、`C:\` 都算空间 | 空间判据是「位置关系」，不是「字符串像路径」 |
| E3 | 程序房收代码 | C12 C13 C16 | 命令行、代码块被当成程序性记忆 | 只看重复出现的做法序列 |
| E4 | 执行房靠词面 | C17 C19 C20 | 原话没有「必须/不许」就漏 | 约束 = 它限制了什么行为 |
| E5 | 显著房靠情绪字 | C22 C23 | 技术讨论里的「怕」「烦」被召回 | 情绪项要挂在具体事上 |
| E6 | 跨房靠词共现 | C26 C30 | 两个词一起出现就互相开门 | 只认四类桥 |
| E7 | 该召没召 | C09 C10 C11 | 位置记错或入口说不出 | 摘要定位器形态要能指回原文 |
| E8 | 老事重复 | C03 C04 | 同一件事投影成多条，召回时刷屏 | 同源即突触：共享 frag_id 的投影合并 |
| E9 | 关系问题硬落房 | C27 | 概念关系被压成某一条事件 | 允许「不落房」 |

## 八、使用方式

1. 第一刀（`frag × term` + 第一版 `room_projection`）跑完，拿这 30 条逐条过。
2. 每条只看两件事：**召回了什么**、**进了哪几间房**。对不上就记进 §七。
3. 错法清单收敛后，才允许把结构正则从落房路径里摘掉。
4. 判据每次改动，重跑这份清单；新的错法追加，已修的不删（留作回归）。

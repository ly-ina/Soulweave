## 〇、结论先说：魂引零注入已修复（commit `a926931`）

**根因是两处宿主契约错误，都在 apply 阶段直接抛异常，插件静默消失**（import 成功、apply 不执行）：

1. `index.js` 导出的 `Config` 是普通对象。cordis `resolveConfig` 只认 standard-schema：
   `runtime.Config['~standard'].validate(config)` → `TypeError: Cannot read properties of undefined (reading 'validate')`。
   **apply 根本不会被调用。**
2. `adapters/dsh/panel.js:197` 访问 `ctx.webServer`，但 `inject` 只有 `['tools']`。
   cordis 按 inject 校验属性访问 → `Error: cannot get property "webServer" without inject`，apply 跑到面板注册处炸掉。

**改法**：

- `Config` 换成合法 standard-schema（`{'~standard': {version:1, vendor:'soulweave', validate(v){return {value:v ?? {}}}}}`）；默认值另导出 `DEFAULT_CONFIG`，运行时仍由 `normalizeConfig` 补。
- `inject = ['tools', 'webServer']`。

**复现与验证**（可复用）：

- 最小 cordis 宿主在 `E:\dsh_work\lanxi\tmp\cordis-test\`（从 asar 抽 `@deepseek-ai/cordis` + `cosmokit`）。
  `test2.mjs` / `test3.mjs` 能直接分辨「apply 没被调用」还是「apply 抛了」。
- 修复后：`apply` 63 ms 走完，注册 `agent/pre-step ×1`、`session/event ×4`、13 个工具；
  宿主热重载后 `soul.log` 出现 `inject ...` + `pre-step ok ...`，魂引回到上下文。

**已清理**：`index.js` 的 boot.log 哨兵与 `traceApply`、`adapters/dsh/apply.mjs` 的 `tracedPreStep` 与五段 apply 打点，全部删除。

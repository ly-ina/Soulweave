## 一、两条硬约束

1. **写入零模型，读出才用模型。**
2. **新增的魂汐层尽量不量化。**
   阻尼、势能机已经量化的部分保留不动；此后新加的判断用资格、集合、顺序，不用分数和阈值。

### 为什么取消量化

量化在调参时方便，但在长期运行的记忆系统里有三个致命伤：

- **阈值是脆的**：换语料、换长度、换话题比例，同一个数字就失效。
- **分数不可复述**：说得出「0.83」，说不出「为什么是 0.83」。出错了没法归因。
- **加权求和会互相抵消**：三个维度各错一点，总分还是中等——它把「错」平均掉了。

替代方案：

| 量化做法 | 非量化替代 | 效果 |
|---|---|---|
| 阈值判定 | **资格**：有 / 没有 | 可复述，出错能一句话说清 |
| 加权求和 | **字典序**：先房间、再锚、再时间 | 重要维度不被小错抵消 |
| 相似度分数 | **集合关系**：同房 / 共享锚 / 有边 | 不需要标定 |
| 命中率百分比 | **错法清单**：哪条错、错在哪 | 改进方向直接可见 |

**排序用字典序，不用总分。** 这是最关键的一条：先按房间筛，房间内按锚筛，都平了再看时间。没有权重这个东西。

## 三、房间体系

**房间不是新造的概念，数据里已经有了三级，只是检索不认它。**

| 层级 | 现有字段 | 现有分布 | 类比 |
|---|---|---|---|
| 分区 | `summary.zone` | intimacy 3 735 / work 2 526 / misc 943 / rules 745 / relations 69 | 大脑分区 |
| **房间** | `memories.project`、会话主题 | lumi-game 149 / 全局 71 / dsh 59 / soulweave 33 … | 房间 |
| 位置 | `summary.scene_id` | `session:turn`，594 个 | 房间里的一处 |

### 检索边界

```
默认：只在当前房间内召回
跨房：必须满足跨区条件（见下），且要能说出「为什么跨了」
```

### 跨区条件（存在性判断，不是权重）

跨区是**有桥才跨**，不是「有点像就跨」。四条桥，满足任一条即可：

1. **用户主动提起**：查询里出现了另一个房间的专名 / 实体 / 文件路径。
2. **共享锚人**：两个房间共享同一个人（伊纳、小汐），且查询本身在问关系。
3. **同一条因果链**：`memory_edge` 上有边——这件事当时导致了那件事。
4. **同一项目名**：`project` 字段相同，只是会话不同。

**反例**：查询里出现「重启」，work 房间和 intimacy 房间都聊过重启——这**不是**桥，只是词重合。跨区判断必须落在「谁 / 哪个项目 / 哪条因果」，不能落在词。

这条很重要：**词共现不构成跨区理由。**

## 五、每阶段细则

### 阶段 0 · 案例集（第一个动手的）

**不写指标的替代品：写案例。**

20–30 条真实查询，覆盖不同房间，每条记三样：

```
查询原文
该召回什么（具体到哪条记忆/哪段对话）
该不该跨房 —— 如果该跨，是哪条桥
```

跑完不是算分，是**逐条看错在哪**：

- 房间错 → 阶段 1
- 切得糊 → 阶段 2/3
- 召回了不该召的（跨区乱跑）→ 阶段 1/7
- 该召的没召到（房间里根本没有）→ 阶段 4

产出是一份**错法清单**，不是百分比。

---

### 阶段 1 · 房间 + 跨区

**现在**：`retrieve` 全库打分，zone/project 只是标签。

**做法**：
1. 定当前房间：默认 `project` + 当前会话主题；切会话时重定。
2. 检索先在该房间内做。
3. 房间内不够、或命中跨区桥，才出房间。

**验收**：每条跨区结果都能说出是哪条桥；说不出 = 不该跨。

**风险**：房间定错的代价是整轮全错。所以房间判定要保守——**判不准就留在当前房间**，宁可少召回，不要乱召回。

---

### 阶段 2 · 切分

**问题**：`splitFragments(max:500, overlap:80)` 定长切；`summary` 按 turn 切。两处都不是「一件事」。

**做法**：TextTiling——用相邻段落的词法衔接找话题突变。

**验收**：抽 20 段人工读，逐段回答「这是一件事，还是两件事」。错几条记几条。

**风险**：短对话切不出来。保底：切不出来就整段作为一段。

---

### 阶段 3 · 摘要器改成定位器

**现在**：抽 1–3 句，≤220 字，定位不清。

**改成**：

```
fingerprint = {
  抽取句      : MMR 选出的 1–3 句（原文逐字，不改写）
  kw 骨架     : 3–8 个词，按「能不能区分房间」排序
  时间        : t
  frag 范围   : [frag_id ...]
}
```

**验收**：抽 20 条，只看 fingerprint，能不能唯一指向一条原文。指不到 = 太糊。

---

### 阶段 4 · 质量门

**判据（非量化）**：这段原文带来了**房间里还没有的东西**吗？

```
这段里的词 / 组合，房间里已经有过的 → 不出摘要
出现了房间里没有的锚（新人、新项目、新决定、新关系）→ 出
```

**保底**：没出摘要的 frag 仍可被 BM25 直接命中。

**验收**：每次放行/拦截都能一句话解释。解释不出来 = 判据错了。

---

### 阶段 5 · 词表自进化

**现状**：`appendLearned` 写好了，**全仓库零调用**；`lexicon-learned.txt` 14 个词是手写的。

**做法**：
1. **新词发现**：凝固度（内部互信息）+ 左右熵（边界自由度）→ 候选词
2. 候选过 `appendLearned`
3. **同义合并**：两个词的共现集合互相包含 → 合并到熟的那个，生僻的留别名

注意第 3 条是**集合包含**，不是余弦阈值——同一批 summary 里出现的词，集合近乎相等就合并。

**验收**：连续跑一批 frag，新词自动入库；抽查是不是真词。

---

### 阶段 6 · 共现网络

**现状**：`kw_link` 有权重（0.86–38.6），是 tf 权重，不压高频词。

**做法**：
- 权重改成「**共现关系的显著性**」：两个词一起出现这件事本身有多意外
- 防漂移三约束：权重封顶 / 时间衰减 / 重建时整体归一

**规模**：6 272 词，全对全比较毫秒级，不需要 ANN、不需要降维。

**验收**：抽 20 对词，说得出它们该不该像。说不出 = 网络没学到东西。

---

### 阶段 7 · 激活门

**判据（非量化）**：

```
一个词出现在多个房间 → 跨房词 → 不许单独开门
一个词只出现在一个房间 → 该房间的情景词 → 可开门

激活 = (≥1 个本房间情景词)
     OR (≥2 个不同跨房词同时命中)      ← 关系类：「小汐 + 伊纳」
     OR (1 跨房词 + 1 情景词)
单个跨房词 → 只过滤，不激活
```

这比「时间覆盖率 0.3」更干净：**信息量来自区分能力**，而不是出现频率。小汐出现在所有房间，所以它不区分任何东西。

**验收**：跨房词单命中不产生注入；每次注入能说出是哪个情景词开的门。

---

### 阶段 8 · 读出闭环

**做法**：
- 召回 → 输出 → 输出写回 frag → 自动归入房间
- **inhibition of return**：同一个锚最近刚被想起来的，下一轮不再重复开门
- momentum 接线：`prestep` 每轮 `observe`；`assocByPPR` 传 `alpha`；compaction 喂 `compacted`

**验收**：连跑几天，不出现「老是想起同一件事」。

## 六、明确不做

| 不做 | 原因 |
|---|---|
| 遗忘 / 删除层 | 原文 append-only；有限性来自准入，不来自删除 |
| 向量模型 / embedding | 规模小，共现网络够用且可解释 |
| ANN / HNSW 索引 | 6 272 词暴力比较毫秒级 |
| 让模型参与写入 | 违反魂汐原则 |
| **新增数值阈值 / 加权总分** | 违反第二条约束；用资格、集合、字典序代替 |

**例外**：已有的阻尼、势能机保持原样，不回头改。

# 魂汐 · 整体流程与阶段待办

> 2026-11-27 记；同日两改：加「尽量不量化」，再把房间体系换成脑区功能分区。
> 设计原则见 `docs/HUNXI.md`。本文回答：整条闭环长什么样、现在在哪、下一步做什么。

---

## 一、三条硬约束

1. **写入零模型，读出才用模型。**
2. **新增的魂汐层尽量不量化。**
   阻尼、势能机已经量化的部分保留不动；此后新加的判断用资格、集合、顺序，不用分数和阈值。
3. **房间是脑区级功能分区，不是会话隔离。**
   同一次经历在五间房各有落点；房间固定不长，突触可以长。

### 为什么取消量化

量化在调参时方便，但在长期运行的记忆系统里有三个致命伤：

- **阈值是脆的**：换语料、换长度、换话题比例，同一个数字就失效。
- **分数不可复述**：说得出「0.83」，说不出「为什么是 0.83」。出错了没法归因。
- **加权求和会互相抵消**：三个维度各错一点，总分还是中等——它把「错」平均掉了。

替代方案：

| 量化做法 | 非量化替代 | 效果 |
|---|---|---|
| 阈值判定 | **资格**：有 / 没有 | 可复述，出错能一句话说清 |
| 加权求和 | **字典序**：先房间、再锚、再时间 | 重要维度不被小错抵消 |
| 相似度分数 | **集合关系**：同房 / 同源 / 有边 | 不需要标定 |
| 命中率百分比 | **错法清单**：哪条错、错在哪 | 改进方向直接可见 |

**排序用字典序，不用总分。** 没有权重这个东西。

     │             │

                   ▼                               │
         ┌────────────────────┐                    │

         │  ① 查询分词        │                    │
         │  ② 丘脑：路由 + 情绪偏好                   │

## 三、五间房

**同一次经历会在五间房同时留下痕迹，而且是不同的侧面，不是五份副本。**

| 房间 | 脑区 | 真实功能 | 管什么 | 判断问题 | 现有数据 |
|---|---|---|---|---|---|
| **情景房** | 海马体 | 把分散表征绑定成「一次经历」，带时间地点 | 发生了什么、什么时候、跟谁 | 「那次……」 | `frag`、`summary`、`scene_id` |
| **执行房** | 前额叶 | 工作记忆、目标维持、抑制冲动 | 现在的目标、规矩、约束、待办 | 「我该……／不许……」 | `rules`、`todos`、soul 规则 |
| **空间房** | 顶叶 | 空间定位、注意定向、位置整合 | 在哪、指向哪、走哪条路（存储型，最廉价） | 「东西在哪／走哪条路」 | 位置关系：A 在 B 内／从 A 到 B／指向 C |
| **程序房** | 基底核 | 习惯、程序性记忆、动作选择 | 这类事通常怎么做、熟练动作（训练型） | 「怎么弄来着」 | 重复出现的做法序列（跨 frag 复现才算） |
| **显著房** | 杏仁核 | 情绪标记、威胁检测、重要性加权 | 多重要、多危险、对我意味着什么 | 「要紧吗」 | `importance`、intimacy、禁令、※记 |

### 举例：同一段原文，五个落点

```
原文：昨晚 19:40 重启 DSH，因为代理没起；重启前该先确认 7890 端口。
      改的是 E:\dsh_work\plugins\dsh-soulweave。那次有点慌，工作树还没提交。

情景房  昨晚 19:40 重启 DSH，因为代理没起
执行房  重启前要先确认 7890 端口
空间房  E:\dsh_work\plugins\dsh-soulweave
程序房  改完 → check.mjs → check-layers → gen-api --check → 重启
显著房  那次有点慌，工作树没提交
```

**不是副本，是投影。** 问「重启的标准步骤」只进程序房；问「上次重启我慌不慌」要情景房 + 显著房。

### 丘脑：不是房间，是两件事，互不干扰

| 职责 | 做什么 | 非量化形式 |
|---|---|---|
| **路由** | 输入投到哪几间房 | 命中哪几间房的触发词 |
| **情绪偏好** | 在这几间房里，先想起哪类条目 | 标签集合，不是分数 |

**情绪不关房间。** 情绪不会让某个脑区停工——生气时海马体照样记得那次发生了什么，只是偏向委屈而不是温暖。所以情绪作用于**条目**，不作用于房间（2026-11-27 实测修正：原来的「按房间开关」会把情景房关掉，结果紧张时想不起出了什么事）。

条目标签在落点写入时打：`routine / task / warmth / bond / threat / risk / unfinished / grievance / boundary / offense / rule / novelty / achievement / lesson / chatter`。

| 情绪 | 先想起 | 压住 |
|---|---|---|
| 平静 | 常规流程、任务 | 威胁、委屈 |
| 亲近 | 温暖、关系 | 委屈 |
| 紧张／警惕 | 威胁、风险、没完成的事 | 闲聊 |
| 生气 | 边界、被冒犯、规矩 | **温暖**（生气时想不起对方的好） |
| 难过 | 温暖 | 教导 |
| 兴奋 | 新鲜、成就 | — |

**保底：判不出情绪就不设偏好，原序返回。** 误压比不压更糟。

### 判据从矩阵里长，不维护词表

```
房间 = 记忆矩阵上的一个投影
判据 = 该投影的项 profile：稳定只落在这间房的项
跨房项 → 不进任何 profile（不许单独开门）
落房 = 新 frag 的项集与哪间 profile 重叠最多（集合关系，不算分）
```

矩阵变了，profile 自己变；共现散了，项自己掉出去。手写只在冷启动出现，且是一次性脚手架（见 §十一）。

### 同源即突触

同一段原文在几间房各有落点，它们之间**不需要新建边表**——共享 `frag_id` 本身就是那条突触。

想起那晚（情景房），程序房的流程会跟着浮上来，靠的就是这个。

### 房间不长，突触长

聊到摄影不会多出「摄影房」。摄影这件事落在情景房，它的做法落在程序房，它的位置落在空间房。

### 现有 `zone`：不做种子，只做验证集

实测（2026-11-27）：

| 事实 | 数值 |
|---|---|
| zone 在哪 | `summary.zone`，`frag` / `memories` 上都没有 |
| 分布 | intimacy 3 735 / work 2 526 / misc 943 / rules 745 / relations 69 |
| 粒度 | summary 8 018 行（≈一轮一条）vs frag 30 270 |
| summary → frag 指针 | 无，只有 `sid + turn` |
| `scene_id` 覆盖 | summary 60 / 8 018，memories 3 / 723（字段建了没跑） |

不当种子的两个原因：**轴不对**（zone 是话题/轮，房间是记忆类型，两者正交），**粒度不对**（轮 vs 原文，回指只能靠推断）。

保留一次用途：投影跑完后当**事后验证集**——`intimacy` 那 3 735 条里，规则/边界、情绪/在意、发生过的事本该被拆进执行/显著/情景三间；如果整桶原样保留，就是投影没长出来。验完即弃。

## 五、每阶段细则

### 阶段 0 · 案例集（第一个动手的）

**不写指标的替代品：写案例。**

20–30 条真实查询，每条记四样：

```
查询原文
该召回什么（具体到哪条记忆/哪段对话）
该进哪几间房
该不该跨房 —— 该跨的话凭什么
```

跑完逐条看错在哪，产出**错法清单**：

| 错法 | 指向 |
|---|---|
| 房间错（投错房） | 阶段 1 |
| 该跨没跨 / 乱跨 | 阶段 1 / 7 |
| 切得糊（一条落点混了两件事） | 阶段 2 / 3 |
| 该召的没召到 | 阶段 4 |
| 想起来的是同一件老事 | 阶段 8 |

产出是清单，不是百分比。

---

### 阶段 1 · 房间 + 丘脑

**做什么**：
1. 五间房的定义 + **每房一套结构判据**（不靠词表）
2. 丘脑路由：一段原文满足哪几间房的结构判据
3. 投影：每房按自己视角抽取（先用简单规则，切分做好后再精化）
4. 词表只做补充；触发词靠 `syncTriggers` 自己归位

**结构判据**（实测：词表路由 frag 级落空 61%、summary 级落空 78–89%，不可用）：

| 房间 | 判据 |
|---|---|
| 空间房 | 文本含路径/文件名/URL；或该轮 `scene.cwd` / `path_pattern` 非空 |
| 程序房 | 该轮有工具调用（`scene.tool`）；或文本含命令行/代码块 |
| 执行房 | 命中 `todos`；或对应规则文件；或含「该·不许·必须」 |
| 情景房 | 有明确时间指代；或 `role=user` 的陈述句 |
| 显著房 | `importance` 命中；或情绪词 |

**验收**：抽 20 段原文，每个落点能用一句话解释「为什么落这间房」。解释不出 = 判据有问题。

**风险**：投影写得太宽，五间房都落，等于没分。判据要保守——**落点靠证据，不靠联想**。落空率高不是错，硬塞才是错。

---

### 阶段 2 · 切分

**问题**：`splitFragments(max:500, overlap:80)` 定长切；`summary` 按 turn 切。两处都不是「一件事」。

**做法**：TextTiling——用相邻段落的词法衔接找话题突变。

**验收**：抽 20 段人工读，逐段回答「这是一件事，还是两件事」。错几条记几条。

**风险**：短对话切不出来。保底：切不出来就整段一段。

---

### 阶段 3 · 摘要器改成落点

**现在**：抽 1–3 句，≤220 字，不分房。

**改成**：每条落点一个 fingerprint：

```
fingerprint = {
  抽取句      : 该房视角下 MMR 选出的 1–3 句（原文逐字）
  kw 骨架     : 3–8 个词，按「能不能区分房间」排序
  时间        : t
  frag 范围   : [frag_id ...]
}
```

**验收**：抽 20 条，只看某房 fingerprint，能不能唯一指向一条原文。指不到 = 太糊。

---

### 阶段 4 · 质量门

**判据（非量化）**：这段原文带来了**这间房里还没有的东西**吗？

```
这段里的锚（人、项目、决定、关系、坑）这间房里已经有过的 → 不落点
出现了这间房里没有的锚 → 落点
```

**保底**：不落点的 frag 仍可被 BM25 直接命中。

**验收**：每次放行/拦截都能一句话解释。解释不出来 = 判据错了。

---

### 阶段 5 · 词表自进化

**现状**：`appendLearned` 写好了，**全仓库零调用**；`lexicon-learned.txt` 14 个词是手写的。

**做法**：
1. **新词发现**：凝固度（内部互信息）+ 左右熵（边界自由度）→ 候选词
2. 候选过 `appendLearned`
3. **同义合并**：两个词的共现集合互相包含 → 合并到熟的那个，生僻的留别名

第 3 条是**集合包含**，不是余弦阈值。

**验收**：连续跑一批 frag，新词自动入库；抽查是不是真词。

---

### 阶段 6 · 共现网络

**现状**：`kw_link` 有权重（0.86–38.6），是 tf 权重，不压高频词。

**做法**：权重改成「共现关系的显著性」——两个词一起出现这件事本身有多意外。防漂移三约束：权重封顶 / 时间衰减 / 重建时整体归一。

**规模**：6 272 词，全对全比较毫秒级，不需要 ANN、不需要降维。

**验收**：抽 20 对词，说得出它们该不该像。

---

### 阶段 7 · 激活门

```
一个词出现在多间房 → 跨房词 → 不许单独开门
一个词只出现在一间房 → 该房情景词 → 可开门

激活 = (≥1 个本房情景词)
     OR (≥2 个不同跨房词同时命中)      ← 关系类：「小汐 + 伊纳」
     OR (1 跨房词 + 1 情景词)
单个跨房词 → 只过滤，不激活
```

**验收**：跨房词单命中不产生注入；每次注入能说出是哪个情景词开的门。

---

### 阶段 8 · 读出闭环

**做法**：
- 召回 → 输出 → 输出写回 frag → 丘脑重新路由
- **inhibition of return**：同一个锚最近刚被想起来的，下一轮不再重复开门
- momentum 接线：`prestep` 每轮 `observe`；`assocByPPR` 传 `alpha`；compaction 喂 `compacted`

**验收**：连跑几天，不出现「老是想起同一件事」。

## 六、明确不做

| 不做 | 原因 |
|---|---|
| 遗忘 / 删除层 | 原文 append-only；有限性来自准入，不来自删除 |
| 向量模型 / embedding | 规模小，共现网络够用且可解释 |
| ANN / HNSW 索引 | 6 272 词暴力比较毫秒级 |
| 让模型参与写入 | 违反魂汐原则 |
| 新增数值阈值 / 加权总分 | 违反第二条约束 |
| 按会话隔离的房间 | 房间是功能分区，不是会话边界 |

**例外**：已有的阻尼、势能机保持原样，不回头改。

## 八、闭环逻辑：每一圈改了什么

闭环不是"想起来了然后写回去"这一句。每跑一轮，状态变化是确定的：

| 步骤 | 动作 | 表的变化 | 可回退性 |
|---|---|---|---|
| 1 | 一轮对话结束 | `frag` +N（**只增**） | 事实源，不回退 |
| 2 | 切分话题段 | 内存中，不落表 | — |
| 3 | 丘脑路由 | 内存中，不落表 | — |
| 4 | 各房准入 | `room_projection` +0~5 行 | 删该轮 projection 可重跑 |
| 5 | kw 提取 / 归位 | `kw` 可能 +新词；`kw_link` +边 | 全量重建可覆盖 |
| 6 | 用户输出 | 又变成第 1 步的输入 | — |

**幂等的前提**：`frag` 是唯一事实源，其余全是派生。所以任何一步错了都可以删掉重跑，不会污染原文。这是魂汐能"改起来不困难"的根本原因。

### 会不会越跑越乱

| 风险 | 机制 | 应对 |
|---|---|---|
| 房间漂移 | 房间固定五间 | 结构上不可能多出房间 |
| 词表膨胀 | 新词发现无节制 | 准入：只收凝固度 + 左右熵都过关的；真词有限 |
| 突触膨胀 | `memory_edge` / 同源连接只增不减 | 长期未被同源激活的连接直接断开（存在/不存在，不打分） |
| 回音室 | 想起过的越容易被再想起 | inhibition of return：同一个锚最近刚开过门，下一轮不开 |
| 投影写宽 | 五房全落 = 没分 | 落点靠证据不靠联想；宁可少落 |

### 一层出错怎么退

- 每个阶段独立开关（config），关掉后回落到上一版行为
- `room_projection` / `summary` 可按轮删除重算
- 词表可从 `frag` 全量重建
- **原文永远不动**

## 九、可行性

### 已验证（有实测数字）

| 假设 | 结果 |
|---|---|
| 分词可用 | ✅ 词表 104 920 条正常加载，能切出「上次」「担心」等 |
| 抽取式摘要在跑 | ✅ 8 018 条 `extractive-v1` 已落库 |
| 房间靠触发词路由 | ❌ **不成立**。frag 级落空 61%，summary 级落空 78–89% |
| 房间数据存在 | ✅ `zone` / `project` / `scene` 都有数据可用 |
| **改结构判据后** | ✅ 300 条随机 frag：底座 100%，空间房 26.0%，执行房 15.7%，显著房 8.3%，程序房 6.0% |
| **每个落点可解释** | ✅ `explainRoute()` 返回证据原文片段，空间房抽样 14 条全是真路径/文件名 |

**结论**：路由确定用结构判据（路径 / 工具调用 / 规矩 / 时间 / 情绪），词表只做补充；**情景房是底座**，所以不存在「落空」。
判据要回答的是「除了底座，还多了哪几间」。

两条已知的收窄经验：

- 路径正则别贪：`DSH/cordis`、`.self-gauge.merged`、`taskkill /T` 都会被误判成路径。要求盘符 / 两段以上带分隔符 / 明确扩展名，三条之一。
- **投影在 frag 或话题段上做，不在 summary 上做**。summary 平均 39 字，信息只剩骨架，83% 只剩底座房。

### 未验证（必须先验，再往下写）

| 假设 | 怎么验 | 不成立怎么办 |
|---|---|---|
| 结构判据覆盖率够 | 200 条 frag 按结构判据重跑，看落空率 | 落空仍高 → 缩小房间数或引入「未归属」房间 |
| 抽取式能做定位器 | 抽 20 条落点，只看它能否唯一定位原文 | 定位不住 → 加更多原文逐字片段，接受更长 |
| 非量化切分可行 | 用「新锚出现」当话题边界，看切得对不对 | 不行 → 保留定长切，切分暂缓 |
| 情绪判定可做 | 写入只用词表+结构线索；读出交给小汐 | 写入判不出 → 只走读出路径，不落情绪标签 |

### 已知的技术冲突

1. **TextTiling 与「不量化」冲突。** TextTiling 本质是算相邻段落的词汇相似度，需要阈值。
   → 改成结构判据：**话题边界 = 出现了此前段落没出现过的锚（人名/项目/文件/术语）**。是存在性判断，不是相似度。
2. **情绪判定与「写入零模型」冲突。** 写入路径不能用模型，就没法真判情绪。
   → 写入只打"可观测的情绪线索"标签（词表 + 结构），真正的情绪判定放在读出路径由小汐做。
3. **跨房词随语料增长会变多。** 常见词最终会出现在所有房间，激活门会失效。
   → 这不是缺陷：常见词本来就不该单独构成证据。但要观测「还能开门的词」是否一直够用。

### 存储与性能

| 项 | 估算 |
|---|---|
| `room_projection` 新增行 | 每轮 0–5 行，按平均 1.5 算，一年约 1–2 万行 |
| 每行大小 | 抽取句 + kw 骨架，约 200–400 字节 |
| 新增存储 | 一年 几 MB，可忽略 |
| 路由耗时 | 每轮一次，纯规则判断，微秒级 |
| 全对全词比较 | 6 272 词，毫秒级，不需要 ANN |

**结论：规模不是瓶颈，判断质量才是。**

## 十、自进化：判据怎么长

**魂汐的核心不是五间房，是判据会自己长。** 房间只是骨架，长出来的投影才是肉。

### 机制

```
矩阵投影给出每间房的项 profile（判据本体）
    ↓
结构判据只在冷启动跑一次，落第一版投影
    ↓
投影跑完，结构判据退场；落房只看项集重叠
    ↓
矩阵变化 → profile 重算 → 判据自己变
```

### 三条防自我强化（缺一条就塌）

1. **无投影不判**：新 frag 先落底座房（情景房）；要进别的房，必须有矩阵里已有的项支撑。靠结构正则落进来的样本不参与 profile 计算——否则「判了所以成为判据，成为判据所以判」，一圈就漂走。
2. **跨房项不进 profile**：一个项在多间房稳定出现，就不属于任何一间，从所有 profile 里排除。
3. **撤销是重算**：profile 是派生数据，矩阵一变重算即撤销，不需要单独的撤销逻辑。

另有一条资格：**一次可能是巧合，复现才收**。

### 关键经验（2026-11-27 三次实测迭代，已作废）

> 这三次都在「从证据句里抽词」这个前提下做。前提本身错了——判据来源应是矩阵。数字只留作旧做法的证据。

| 迭代 | 做法 | 结果 |
|---|---|---|
| v1 | 从整段学 | 空间房吸收整段技术讨论，「认知」「过程」「向量」被当成空间词 |
| v2 | 只从**证据所在的那一句**学 | 明显变干净，但单条证据仍是噪声源（` ``` ` 让程序房学到一堆绘图提示词） |
| v3 | **强锚**（同房两条以上独立证据）+ 只学纯中文 2–4 字词 | 词面干净了，学的仍是「文本里的词」，不是「矩阵里的项」 |

**结论（修正后）：学习质量不由锚的宽窄决定，由判据的来源决定。词面再干净，来源是文本就还是词表。**

### 每间房判据的形态不同（2026-11-27 重定）

| 房间 | 记忆类型 | 判据形态 | 不是什么 |
|---|---|---|---|
| 情景房 | 自传体事件 | 时间 + 人 + 经过 | 不是「含时间词」 |
| 空间房 | 位置/指向/路径（存储型，最廉价） | **位置关系**：A 在 B 内、从 A 到 B、指向 C | 不是路径字符串模式 |
| 程序房 | 习惯/程序性记忆/动作选择（训练型） | **重复出现的做法序列**：遇到 X 就 Y、先 A 再 B | 不是代码、不是命令行、不是工具名 |
| 执行房 | 规则/边界/承诺 | 约束项 + 它约束的对象共现 | 不是「含必须/不许」 |
| 显著房 | 情绪标记/在意 | 情绪项 + 它挂在哪件事上共现 | 不是「含怕/喜欢」 |

**程序房学到 0 个不是语料问题，是判据错了**：我拿命令行当成了程序性记忆。按新语义，它的语料是「这类事通常怎么做」，来源是同一类事在多次 frag 里重复的做法，不是某条命令。

### 实测数字（3 000 条随机 frag）

```
有证据句         1 279 (42.6%)
观察到候选词     2 466
培养成功           292
跨房撤销         1 010  (41%)
```

撤销率高是好事——守卫在工作。

### 还有一条没做：判据要能被人看

判据必须可查看、可解释（「这个项凭什么属于这间房」）、可撤销。但撤销不是单独动作——profile 是算出来的，改了矩阵重算即可。需要的是一个出口：`hunxi explain <term>` 返回它落在哪些房、来自哪些 frag 的共现。这是阶段 1 的一部分。

## 十一、第一刀：先补原文级矩阵，再做投影

**顺序不能反。** 现在 `kw_link` 的键是 `summary_id + kw_id`（34 152 条，全连在 8 018 条摘要上），原文 `frag` 没有词链接。拿摘要级矩阵投影，上限就是一轮摘要的粒度（平均 39 字，实测 83% 只剩底座房）。

| 步 | 动作 | 产物 | 可逆性 |
|---|---|---|---|
| 1 | 用现成切词器扫 30 270 条 `frag` 原文，建 `frag × term` | 原文级矩阵 | 派生数据，删表可重跑 |
| 2 | 结构判据跑一遍（**只此一次**），落第一版房间投影 | `room_projection(frag_id, room, evidence)` | 可重跑 |
| 3 | 从投影反推每房项 profile（稳定只落该房的项；跨房项排除） | profile | 算出来的，全部不落库也行 |
| 4 | 拿 `zone` 当验证集对照（见 §三） | 一份错法清单 | 一次性，验完即弃 |

跑完这四步，结构正则退场，之后落房只看 profile 重叠。

**判定第一刀成功的标准不是命中率，是错法清单**：`intimacy` 桶里有没有被拆开、`work` 桶里「改 config」和「npm 被拉黑」有没有分开、程序房有没有学到「先改再 check 再重启」这类序列。

### 实测：第一版（2026-11-27，3 000 条样本）

工具已落地：`tools/hunxi-matrix.mjs`（建原文级矩阵）、`tools/hunxi-project.mjs`（第一版投影 + profile）。全量矩阵 707 303 行 / 37 340 项 / 复现≥2 共 25 114 项。

投影分布（有重叠）：episode 3 000 / spatial 930 / executive 733 / procedural 355 / salient 199。
每房 own 项：spatial 1 020 · executive 663 · procedural 147 · salient 106。
随机 500 条回判：only 171 · multi 124 · none 205（**41% 落空**）。

**四个错法，全部指向同一件事：污染源是 frag 的构成，不是正则松紧。**

| # | 现象 | 根因 |
|---|---|---|
| 1 | 空间房 own 被代码占满：memory / dsh-soulweave / add / context / end / docs / github.com | 58% 的 frag 是 assistant 输出（17 626 条），路径在代码块里的密度远高于真实位置叙述 |
| 2 | 执行房 own 混进「难受」「故事」 | 脚手架按**整条 frag**落房，同一条里既有约束又有情绪，证据不落句 |
| 3 | 程序房 own 是「溯源 / 深度 / 肩上 / 曲线 / 肚子」 | `先…再…` 匹配到散文里的比喻，不是做法序列 |
| 4 | 显著房 own 反而最干净：小小 / 怀里 / 胸口 / 额头 / 奖励 / 听话 | 情绪词几乎不出现在代码里——这一间可以被词面带起来 |

补充数据：frag 角色 = assistant 17 626 / user 9 443 / summary 3 201；长度 200–1k 字 13 036、40–200 字 7 359、<40 字 9 875；空词 2 289 条（纯符号/工具输出）。

### 修正一：路径是产物，不是目标（2026-11-27 伊纳）

> 「路径不应该作为投影，因为路径是产物不是目标。」

`matrix.mjs` 加 `isArtifactTerm()`：路径、文件名、命令、标识符、纯数字一律不进 profile。
它们是那次动作的落点，不是这条记忆的主题。

投影 v2 = 证据落句 + role 分层（summary 不进非底座房）+ 代码块不落房 + 产物过滤。全量 30 270 条实测：

| 房 | 落了 | own 项 | 观感 |
|---|---|---|---|
| spatial | 4 414 | 621 | 装配 / 姓名 / 先行 / 态度 / 音色…散 |
| executive | 4 087 | 673 | 胳膊 / 义务 / 审批权 / 禁区…半对半错 |
| procedural | 2 312 | 189 | 藏青 / 加快 / 若是 / 发虚…散 |
| salient | 1 401 | 263 | 手臂 / 抚摸 / 鼻子 / 被窝…反而能看出情绪 |

随机 500 条回判：only 89 · multi 11 · none 400（**80% 落空**）。

**这不是「还没调好」，是判据的定义出了问题。** `own` 项算的是「只在这间房出现」——稀有词天然满足，于是最稀有的噪声词成了判据。**独占性测的是稀有度，不是意义。**

### 下一步两条候选（待定）

- **A｜锚实例 + 交集**：房间不靠 own 差集，靠几条典型 frag 的共同项；交集天然抗噪，但需要先有「典型 frag」。
- **B｜不做 profile，直接实例比对**：新 frag 的项集和已有 frag 比重叠，继承房间。这是「同源即突触」的直接用法，但重叠计数要小心别滑回量化。

两条都还是从矩阵来，不是手写词表。
